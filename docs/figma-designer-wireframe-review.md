# 디자이너 임시 와이어프레임 검토

2026-09-23. Figma MCP로 섹션 메타데이터, 전체 이미지 및 주요 화면 4개 이미지를 확인했다. Figma 수정이나 제품 구현은 하지 않았다. 프로토타입 인터랙션 실행·색상 대비 측정은 수행하지 않았다.

원본: https://www.figma.com/design/6mcppTWeM18HIPIQTEv0uD/Hello-Protein?node-id=313-1951

섹션 이름은 `250309_소연 와이어프레임`. 이 이름만으로 최종 수정일이나 확정 디자인이라고 판단하지 않는다.

## 확인한 기존 의도

- 목표 직접 입력, 선택적 계산기 바텀시트, 계산 결과를 목표 입력란으로 반영.
- 계산기 단계: 몸무게·활동량·옵션. 옵션에는 해당 없음/60세 이상/수유/임신 등이 있음.
- 홈: 가로 날짜 탐색, 오늘 복귀, 선택 날짜, 섭취량/목표, 선형 진행률, 음식 목록. 빈 상태/진행 중/다른 날짜 달성·미달 상태.
- 하단: 히스토리, 중앙 추가 버튼, 설정. 이전에 제안한 기록/통계/설정 3탭과 다른 구조.
- 추가: 새로 검색/즐겨찾기, 음식별 섭취량·단백질 확인, 여러 항목을 선택해 한 번에 추가. 주석에 검색창/탭 고정, 목록만 스크롤 의도가 있음.
- 히스토리: 캘린더/그래프 전환, 선택 날짜의 음식 목록. 그래프 드래그로 수치 표시 및 선택 날짜 목록, 확대해 월→주 탐색하는 메모.
- 설정: 목표, 검색 언어, Q&A, 오픈소스.

## 유지할 방향

단백질 기록에 집중한 홈, 원형 차트보다 적은 높이를 쓰는 선형 진행률, 가까운 날짜를 빠르게 넘기는 구조, 한 번에 여러 음식을 기록하는 흐름을 우선 활용한다. 새 디자인을 백지에서 만들기보다 기존 두 Figma 기획을 합쳐 상세 동작을 정한다.

히스토리 안에서 캘린더/그래프를 전환하는 구성도 유효하다. 앞서 제안한 3탭 구조를 확정안으로 취급하지 않는다. 기본 화면의 기록 진입과 히스토리 내 상세 화면이 같은 편집 규칙을 쓰도록 설계한다.

## 구현 전 보완할 사항

1. 날짜 선택 줄의 숫자가 날짜인지 섭취량인지 모호하다. 요일+날짜를 기본으로 두고 섭취량에는 g를 붙여 별도 표시한다. 선택 상태와 목표 달성 상태는 서로 다른 시각 표현을 쓴다.
2. 진행률의 둥근 손잡이는 조절 가능한 슬라이더처럼 보인다. 조회용 진행 막대라면 손잡이를 제거하고 실제 섭취량/목표를 명확히 표시한다.
3. 과거 날짜 화면에 수정 텍스트는 있지만 개별 기록 편집 시트·삭제·취소·저장 동작은 확인되지 않았다. 음식 행 탭으로 편집, 선택 날짜를 유지한 누락 기록 추가, 삭제 후 실행 취소를 보완한다.
4. 과거 화면의 목표량 수정은 적용 범위를 밝혀야 한다. 오늘 이후 목표 변경과 특정 과거 날짜 목표 보정을 구분하고, 목표 이력이 없는 구버전 날짜의 달성 여부를 추정하지 않는다.
5. 추가 화면에서 수동 입력 진입점이 명확하지 않다. 새로 검색/즐겨찾기 외에 직접 입력을 항상 찾을 수 있게 한다. AI는 선택적 입력 도구로 추가한다.
6. 다중 선택에는 선택 개수·합계·기록할 날짜를 표시한다. 예: `3개 음식 · 단백질 42g 추가`. 검색어/탭을 바꿔도 선택 상태를 유지하며, 체크와 X가 각각 선택 해제인지 제거인지 역할을 구분한다.
7. 음식 섭취량과 단백질 함량을 독립적으로 수정할 때 계산 관계가 모호하다. 검증된 기준량으로 자동 계산하고 수동 보정 시 의미를 명시한다. 제공량 출처 확인은 별도 필요하다.
8. 그래프 확대 제스처만으로 주/월 이동을 제공하지 않고 명시적인 기간 선택도 제공한다. 캘린더/그래프에서 선택한 날짜는 같은 기록 목록·편집 경로로 연결한다.
9. 마이그레이션된 합계만 있는 날짜는 음식 없음/0g과 구분한다. `이전 버전에서 일일 합계만 보관된 기록` 상태 및 합계 보정/새 항목 추가 정책이 필요하다.
10. 기존 사용자에게 목표 설정을 다시 강제하지 않는다. 임신/수유/고령 옵션은 계산 근거와 적용 정책 확인 전 그대로 구현하지 않는다. 목업의 21g은 검증된 권장량으로 취급하지 않는다.
11. 흑백 임시 와이어프레임으로 색상·최종 대비 수준은 판단하지 않는다. 실제 영문 긴 이름, 큰 글자, 키보드, 하단 안전 영역, 로딩·오류 상태를 추가한다. 목업의 날짜·합계 수치 불일치는 구현 규칙으로 옮기지 않는다.

## SwiftUI 연결 제안

날짜 탐색, 섭취 요약, 음식 행, 추가 초안 목록을 분리 가능한 화면 구성으로 본다. `selectedDate`, 미저장 선택 항목, 편집 중 항목, 기록 로딩/실패 상태를 구분한다. View는 저장소 객체를 직접 변경하지 않는다. 이 디자인을 보고 특정 DB 교체나 Android 기술을 확정하지 않는다.

AI 체험 3회는 앞선 대화의 실험 제안이며 이 Figma에 있는 내용은 아니다. 향후 성공 저장 후 차감·실패/취소 미차감·기존 기록 유지 조건을 추가 설계한다.
