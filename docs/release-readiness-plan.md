# iOS 출시 준비 계획 및 점검 기록

작성: 2026-10-27. 기준: main `6d3b392e27bfe0470ab5913ed68d0c790c1cf15f` (PR #11–13 머지 완료).

## 현재 결론

섭취량·통계까지 개발 검증은 완료됐지만 출시 준비 완료는 아니다. 일반 사용자는 아직 기존 UIKit으로 진입한다. 기존 설정 일부의 새 화면 접근, 실제 구버전 데이터 검증, 배포 구성과 활성화 절차가 남아 있다. 이 문서는 점검 결과와 다음 구현·검증 순서를 함께 제공한다.

이번 작업은 문서 정리·코드/설정 점검·Release 시뮬레이터 빌드까지다. 실기기 설치, 실사용 원본 변경, renewal 기본 활성화, TestFlight 업로드, 정식 배포는 하지 않는다. 역할별 항목은 향후 담당 업무이며 별도 직원/에이전트의 검토 완료를 의미하지 않는다.

## 2. 기존 사용자 이관 검증 — 개발 검증 완료, 실데이터 입력 대기

### 확보된 근거

- PR #13 통합 소스: Core 100, MigrationCore 82, 앱 135 테스트 통과.
- 앱 테스트에 Realm 원본을 변경하지 않는 사본 읽기/백업, 실행 경로 판정 검증이 포함된다.
- MigrationCore에 합계·상세·즐겨찾기·설정 보존, 중복/모호한 날짜 거부, 음수 합계, 중단 후 재개, schema 1/2 승격, 백업 불일치/손상 처리 검증이 있다.
- 기존 시뮬레이터 증거: [Realm 이관·중단·복구](evidence/2026-09-28-simulator/README.md), [schema 3 승격 및 최종 통합](evidence/2026-10-14-quantity-statistics/README.md).
- 이 근거는 합성 데이터와 개발 상태 검증이다. 실제 App Store 배포본의 모든 Realm 형식·사용자 데이터 조합을 검증했다는 뜻이 아니다.

### 실제 파일 접수 조건

사용자에게 기존 백업의 로컬 경로를 요청했다. 아직 제공된 경로가 없다. 저장소에서 실제 사용자 Realm·UserDefaults 백업은 확인되지 않았다. 임의로 다른 앱/기기 컨테이너를 뒤지거나 실기기에서 추출하지 않는다.

필요 자료: 구버전 앱의 정확한 버전/빌드, 앱을 종료한 상태에서 얻은 전체 데이터 컨테이너 복사본(Realm 파일과 관련 파일 포함), UserDefaults plist, 캡처 시각·기기 시간대. 음식 목록과 설정이 서로 다른 시점의 자료인지 확인한다. `Date` 값의 형식을 보존하며 화면에 보이는 합계만으로 이관 성공을 판단하지 않는다.

### 경로 확보 후 실행 절차

1. 원본 백업을 읽기 전용 기준본으로 두고 파일별 SHA-256·크기 목록을 로컬에 기록한다. 실제 음식명·기록·키·원본 파일은 Git/PR에 올리지 않는다.
2. 작업 복사본을 별도 디렉터리에 만든다. 실제 파일은 기존 `RealmLegacySourceGateway`와 같은 사본 읽기 경로로 읽는다. 원본 Realm을 직접 열거나 포맷 업그레이드하지 않는다.
3. UserDefaults를 격리된 테스트 suite에 넣어 같은 캡처 시점으로 해석한다. 날짜 객체/문자열, 누락/0/비정상 값을 구분한다. 기존 앱의 날짜 변경 초기화 코드를 실행해 자료를 변형하지 않는다.
4. LegacyCapture → 검증/매핑 → schema 3 저장을 임시 저장소에 수행한다. 실행 시각·시간대·커밋을 기록한다.
5. 날짜별 상세 수·합계·레거시 보정/원본 총량, 즐겨찾기 순서/값, 검색 이력 순서/언어, 목표 유효 시작일과 검토 필요 상태를 비교한다. 구버전에 없는 과거 음식 상세는 생성하지 않는다.
6. 재실행 시 중복 기록/재이관이 없는지 확인한다. 기존 schema 1/2 사용자 경로도 별도 검증 자료로 유지한다.
7. 복사본만 사용해 교체 전/후 중단, 저장소 손상·누락, 완료/승격 증거만 남은 상태를 확인한다. 새 저장소 증거가 있으면 구 UIKit으로 돌아가지 않아야 한다.
8. 실행 후 원본 백업의 SHA-256이 동일한지 확인하고 익명화된 집계·통과/실패만 증거 문서에 남긴다.

완료 조건: 실제 구버전 자료의 출처 확인, 불일치 없는 대조표, 원본 불변, 재실행 중복 없음. 읽기 실패/날짜 모호성은 자동 초기화나 값 보정으로 덮지 않고 출시 차단 항목으로 기록한다. 실행기 없이 계획만 작성한 상태를 실제 검증 완료로 표시하지 않는다.

### 기본 활성화와 복구 정책

- 현재는 일반 TestFlight 설치에서도 자동으로 새 흐름을 체험할 수 없다. 베타 대상 활성화 방식을 실제 코드/배포 구성으로 먼저 구현·검증해야 한다. Xcode 실행 인자를 TestFlight 사용자에게 전달하는 방식으로 대체하지 않는다.
- 새 저장소로 전환한 사용자를 플래그 하나로 구 UIKit에 돌려보내면 데이터가 분리된다. 이를 롤백 계획으로 사용하지 않는다.
- 이상 발견 시 신규 배포/전환을 멈추고, 이미 전환한 사용자에게는 새 저장소를 읽는 수정 버전을 제공한다. 업그레이드 이전 앱 바이너리 재배포가 schema 3을 읽을 수 있다고 가정하지 않는다.
- 복구 화면은 자동 초기화·원본 삭제를 하지 않는다. 지원 문의 동선과 진단 정보 범위를 정해 실제 기록을 무단 전송하지 않는다.

## 4. 베타·출시 진행 조건 — 아직 실행하지 않음

1. 설정/정보 접근 보완과 계산기/지원 OS 정책을 확정한다.
2. 실제 구버전 복사본 이관 검증을 통과한다.
3. 배포 계정·서명·버전·MFDS 설정을 최종 산출물로 확인하고 활성화 변경을 검증한다.
4. 사용자가 실기기 검증을 요청하면 `devicectl list devices`로 Som을 확인해 삭제 없는 업데이트 설치를 수행한다. 합성 seed/실패 주입 인자는 사용하지 않는다.
5. 업로드할 버전·변경 설명·검증 결과를 확정한 후 TestFlight 배포를 진행한다. 이번 작업의 완료 상태와 혼동하지 않는다.
6. 베타에서 업그레이드/신규 설치·한영 검색·오프라인·일자 변경·재실행·과거 기록 수정·통계·복구를 점검하고, 사용자 데이터 누락·중복·잘못된 날짜가 발생하면 정식 출시를 진행하지 않는다.

Android·AI·구독은 이번 iOS 출시 준비와 별도 작업이다. 기존 무료 기록/즐겨찾기 접근을 출시 준비 과정에서 제한하지 않는다.
