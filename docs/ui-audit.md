## 1. 기존 앱: 화면과 시각 체계 (관찰)

### 1.1 구조
- 탭 바·segue 없음. 모든 전환은 코드. 진입: `targetProtein`이 UserDefaults에 없으면 Init(온보딩), 있으면 Show(홈). `SceneDelegate.swift:84-90`.
- `Init → push Show`, `Show → push Stats`(왼쪽 바 버튼 `chart.bar.xaxis`), `Show → push Setting`(오른쪽 `gearshape.fill`), `Show → 전체화면 present Add`, `Add → sheet Search`, `Setting → push 목표/검색 언어/오픈소스`.
- 홈은 **항상 오늘**이다. 다른 날짜를 보는 방법이 없다. 날짜가 바뀌면 `viewWillAppear`에서 어제 상세를 `StatProtein` 합계 한 줄로 접고 상세를 지운다(`ShowViewController.swift:41-50`). 이것이 이관 시 "합계만 있는 과거 날짜"가 생긴 이유다.

### 1.2 홈 (Show)
- 요소: 제목 "Today"(Binggrae-Bold 22, 하드코딩 영어), 반지름 120·선 두께 20의 원형 진행 링(트랙 `lightGray`, 진행 `#C8F4C2`, 2초 애니메이션, 1.0 초과 clamp 없음), 중앙 라벨 `"48g / 96g"`(정수만), 링 아래 왼쪽에 34pt `plusButton` 이미지, 화면 폭 65%·높이 45%의 표(셀 높이 134, 흰 배경·`#ACDDAD` 1pt 테두리·radius 5, 이름/양 라벨 가운데 정렬 Binggrae-Bold 16).
- 동작: 추가(+), 스와이프 삭제(확인 없음), 통계·설정 이동. 목표 편집은 설정 안에서만.
- 캡처 B6: 배경 크림, 흑백 아이콘, 링·라벨 외에는 여백이 큼.

### 1.3 추가/검색 (Add, Search)
- 3행 폼: `이름`(돋보기 버튼 → 검색), `단백질양(g)`(숫자 키패드, 5자 제한), `즐겨찾기` 스위치(`onTint #ACDDAD`). 행 라벨은 베이지 칩(`#F2F1E2`, radius 20), 입력란은 흰 배경·`#ACDDAD` 2pt 테두리·radius 20. 버튼 `#ACDDAD`@0.8, 검정 글자, radius 10.
- 음식 = 이름 + 정수 g. 섭취량/제공량 필드 없음. 0 입력이 통과한다(`isValidNumber`의 Zero 미검사).
- 저장 성공 시 "Sucess / Successfully Saved!" 알림, 입력 초기화. 즐겨찾기 표에서 행 선택 후 별도 "추가" 버튼으로 기록.
- 검색: 한국어는 식약처 API 5건, 영어는 로컬 USDA JSON 2332건 **전체 반환(검색어 미사용)**, 영어 결과 선택 시 필드가 채워지지 않는 버그. 최근 검색어 목록(x로 삭제), 결과 헤더 "Result(per 100g)".

### 1.4 통계 (Stats)
- `#ACDDAD` 카드(radius 20) 안의 "평균 섭취량"과 값(Binggrae-Bold 22, 흰 배경 radius 20). 아래 Charts `BarChartView`(막대 `#ACDDAD`, 월~일 고정 7칸, 이번 주만, 페이징·월 보기 없음). 목표선은 주석 처리.

### 1.5 설정 (Setting)
- 2섹션 표: 설정(목표 섭취량 `"120g"`, 검색 언어) / 정보(문의하기 메일, 오픈소스). 셀은 흰 배경·`#ACDDAD` 2pt 테두리·radius 10, disclosure.
- 목표 화면은 온보딩 계산기와 같은 폼. 검색 언어는 두 항목 표, 선택 표시 없음.

### 1.6 온보딩 (Init)
- 한 화면: 민트(`#C8F4C2`) 배경의 "HELLO, Protein!" 워드마크(계란 프라이 로고), 베이지 카드 "Protein Calculator"(몸무게 kg/lbs 피커 + 활동량 3단계 피커 → 계산 → 추천값 라벨), 목표 입력란(HoshiTextField), 8pt `#ACDDAD` 테두리의 "START" 버튼. 캡처 D1.
- 계산식: kg×1.2/1.4/1.6, lbs×0.54/0.64/0.73. 임신·수유·고령 옵션은 없다.

## 2. Figma 의도 (2026-09-23 검토 문서에서 옮김)
- 목표 직접 입력 + 선택적 계산기 바텀시트(몸무게·활동량·옵션). 옵션의 60세 이상/수유/임신은 근거 미확인.
- 홈: 가로 날짜 탐색, 오늘 복귀, 선택 날짜, 섭취량/목표, **선형 진행률**, 음식 목록. 빈 상태/진행 중/다른 날짜 달성·미달 상태.
- 하단: **히스토리 / 중앙 추가 / 설정.**
- 추가: 새로 검색·즐겨찾기, 음식별 섭취량·단백질 확인, 여러 항목 선택 후 한 번에 추가. 검색창·탭 고정, 목록만 스크롤.
- 히스토리: 캘린더/그래프 전환, 선택 날짜의 음식 목록, 그래프 드래그로 수치.
- 설정: 목표, 검색 언어, Q&A, 오픈소스.
- 그 문서가 이미 지적한 미결: 날짜 줄 숫자의 모호함, 슬라이더처럼 보이는 진행률 손잡이, 과거 편집 시트 부재, 과거 목표 수정 범위, 수동 입력 진입점, 다중 선택 표시, 합계만 있는 날짜 구분, 흑백이라 색 판단 불가.

## 3. 현재 SwiftUI 프로토타입 (관찰)
- 구조: `NavigationView` 한 장. 상단 "Today"/제목 "Protein Log"/달력 아이콘, 7일 날짜 띠(◀ ▶ 주 이동), 요약 카드(`secondarySystemBackground`), 기록 List, 하단 고정 파란 "Add protein"(`borderedProminent` = 시스템 accent, AccentColor 미정의라 파랑).
- 요약: 날짜 `2026.09.23`, 합계 40pt rounded bold + "g", 목표가 있으면 `ProgressView`(초록 tint) + "Goal 120g", 없으면 "No goal set/No goal history for this day". 레거시 섹션: "Previous version total", 보정값 `+10g`, "Imported original total 55g", 사용자 수정값, "Edit daily total" 링크.
- 날짜 띠 선택 = **초록 사각 채움**(`Color.green`), 오늘 = 작은 accent 점. 초록이 선택과 목표 진행 두 곳에 쓰인다.
- 편집 시트: Form(날짜·이름·단백질), 취소/저장 툴바, 삭제 섹션, 미확정 안내 섹션 + "Check saved result". 저장 중·미확정 중 입력 잠금, 취소 비활성. 총량 편집 시트도 같은 형태.
- 미확정 배너: 주황 15% 배경, "A save couldn't be confirmed…" + 재확인 버튼.
- 복구: 시스템 배경, title2/body/footnote 스택, "Try again" 텍스트 버튼. Release에서는 상세를 종류 코드만.
- 시각은 전부 시스템 기본값이다. 브랜드 색·서체·로고를 하나도 쓰지 않는다. 다크 모드는 시스템 색을 쓰므로 우연히 동작한다.

## 5. 임시로 정해졌던 것 (최종안이 아님)
현재 프로토타입에서 다음은 기능 검증을 위해 구현자가 임의로 정한 값이며 어떤 자료에도 근거가 없다.
- 날짜 띠의 `Color.green` 채움, radius 12, 높이 58.
- 합계 40pt `.rounded`, 요약 카드의 `secondarySystemBackground`.
- 하단 `borderedProminent` 전체 폭 버튼과 `.ultraThinMaterial` 배경.
- 미확정 배너의 주황 15%.
- 복구 화면의 텍스트 버튼과 여백 24/32.
- 제목 "Protein Log", 모든 `renewal_*` 문구의 어조.
- 시스템 Form/List/Sheet 기본 모양 전체.
