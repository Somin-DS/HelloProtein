# 목표 설정·목표 이력 구현 계획

작성일: 2026-10-06. 상태: 구현 전 계획으로 작성됐고, 같은 날 `feat/renewal-goal-settings` 브랜치에 구현했다.

> 2026-10-06 구현 상태: 실행 결과·캡처·미검증은 [실행 증거](evidence/2026-10-06-goal-settings/README.md)에 기록한다. 계산기·온보딩·전체 설정 화면은 여전히 후속이며 새 흐름 기본 활성화·출시는 하지 않았다.

## 목적과 기준

새 SwiftUI 흐름에서 사용자가 하루 단백질 목표를 직접 설정·변경할 수 있게 한다. 새 목표는 오늘부터 적용하고 이전 날짜의 목표를 보존한다. 유효하게 이관된 목표는 그대로 표시하고, 사용할 수 없는 기존 목표는 원문을 보여주며 새 입력을 받는다.

기준은 [PR #6](https://github.com/Somin-DS/HelloProtein/pull/6)이 병합된 main(`e6acbedf668c30a34349689a906d78b61c936d30`)이다. 착수 시 최신 main과 작업 폴더를 확인한다. 이번 계획 작성 당시 로컬은 PR #6 수정 커밋 `cdcf06b`에 있으며, 무관한 `.DS_Store`·`agents/` 파일을 삭제하거나 일괄 stage하지 않는다.

본사 기획·디자인·개발·QA·마케팅·프롬프트 엔지니어·그로스의 검토를 반영했다. 역할별 판단은 [공동 검토 기록](reviews/2026-10-06-goal-settings-team-review.md)에 남긴다. 이전 작업의 테스트 통과는 이번 구현의 실행 결과가 아니다.

기존 `ui-spec`의 “목표가 있으면 설정에서만 변경”은 설정 화면 연결 이후의 최종 경로다. 이번에는 수정 기능에 도달할 수 있도록 **오늘 홈에 임시 목표 설정/변경 진입점**을 둔다. 과거 날짜 홈에는 목표 편집 링크를 두지 않는다. 계산기와 신규 온보딩은 이번에 구현하지 않았음을 backlog에 명시한다.

## 제품 정책

1. 적용일은 사용자가 고르는 값이 아니다. 시트 진입 직전 주입된 clock과 기기 시간대를 기준으로 오늘을 갱신하고, 그 날짜를 편집 세션에 보관한다.
2. 화면에는 ‘오늘’만 쓰지 않고 실제 적용 날짜를 함께 표시한다. 홈에서 선택한 날짜를 목표 저장 날짜로 사용하지 않는다.
3. 같은 날 두 번 저장하면 그 날짜 항목 하나를 새 값으로 교체한다. 날짜별 적용 이력이며 모든 편집의 감사 로그는 아니다.
4. 이전 날짜의 목표 항목·기록·합계는 보존한다. 최초 목표 적용일보다 이전 날짜에는 목표를 추정하지 않고 기존 `noHistory` 상태를 사용한다.
5. 목표값은 기존 `ProteinInput.parse`를 사용한다. 양수, 소수 최대 두 자리, 지역화된 소수 구분자와 overflow 규칙을 그대로 따른다. 임의 최대값이나 건강 권장량을 새로 정하지 않는다.
6. 현재 목표가 있으면 실제 오늘에 적용되는 값을 입력란에 채운다. 목표 없음 또는 검토 필요 상태에서는 빈칸으로 시작하며 임의 숫자를 넣지 않는다.
7. 변경하지 않은 현재 목표의 저장 버튼은 비활성화한다. 표시 문자열 변경은 Phase 1B처럼 dirty로 판단하되, 파싱한 값이 현재 목표와 같고 검토 flag 정리도 필요 없다면 저장을 비활성화해 불필요한 이력 생성을 막는다. 유효하지 않은 변경 입력은 기존 검증 오류를 안내할 수 있어야 한다.

## 화면 구성과 동작

### 오늘 홈

`DaySummary` 근처에 ‘목표 설정’ 또는 ‘목표 변경’ 텍스트 버튼을 둔다. 최소 44pt 터치 영역을 확보하고 새 탭이나 아이콘만 있는 버튼으로 바꾸지 않는다. 목표 없음·검토 필요는 설정, 유효 목표는 변경이다. 목표 무결성 오류는 오류를 유지하며 정상 편집으로 덮어쓰지 않는다.

진입은 `selectedDay == today`이고 busy/pending이 아닐 때만 가능하다. 버튼 실행 직전 `refreshToday()`로 날짜를 다시 확인한다. 자정이 지나 선택 날짜가 어제가 됐다면 오늘 선택 안내 또는 기존 오늘 버튼으로 이동하게 하며 어제 카드에서 바로 편집을 열지 않는다.

### 목표 시트

- 제목: 하루 단백질 목표.
- 현재 목표와 적용 시작일: `state.goal(on: targetDay)`에서 읽는다. 선택한 과거 날짜용 `model.goalState`를 재사용하지 않는다.
- 새 목표 입력: 명시적 ‘하루 목표 (g)’ label, 기존 숫자 입력 스타일과 decimal keyboard.
- 실제 적용 날짜와 과거 목표 보존 설명.
- 오늘 이미 목표가 있으면 같은 날 교체 설명.
- 검토 필요하면 기존 raw 원문 안내. 텍스트로 그대로 렌더링하고 markdown/포맷 문자열로 해석하지 않는다. nil과 빈 문자열은 누락/빈 값 안내로 구분하며 정상 목표처럼 prefill하지 않는다.
- 접을 수 있는 읽기 전용 ‘목표 이력’. 적용일 내림차순으로 날짜와 g를 표시하고 현재 적용 중인 항목을 구분한다. 이력이 없으면 빈 상태를 표시한다. 항목의 수정·삭제·날짜 이동 동작은 없다.
- 상단 취소·저장, 세로 스크롤과 Dynamic Type. 시트 위에 또 편집 시트를 쌓지 않는다.

이력은 마지막으로 확인된 `state`를 표시한다. 목표를 저장한 것처럼 먼저 보여주는 낙관적 갱신은 하지 않는다. 현재 적용 표시도 날짜 기준 조회 결과와 일치해야 한다. 미래 항목이 외부 fixture에 존재하더라도 ‘현재’로 오표시하거나 이번 저장에서 삭제하지 않는다.

## 자정·날짜 변경 처리

시트 적용 날짜는 자동으로 바뀌지 않는다. VM 저장 진입 시 최신 clock으로 계산한 오늘과 시트 날짜를 비교한다.

- pending이면 원래 작업을 먼저 재확인하고, busy이면 새 동작을 거부한다.
- idle에서 날짜가 다르면 write 0, 입력 유지, 날짜 변경 안내를 반환한다. 임의로 어제에 저장하거나 새 날짜에 자동 저장하지 않는다.
- 시트에 새 실제 날짜와 ‘적용일을 오늘로 변경’ 동작을 제공한다. 사용자가 이를 선택하면 입력은 유지하고 세션 적용일만 최신 오늘로 갱신한다. 다시 저장해야 기록된다.
- stale 상태에서는 ‘오늘부터 적용’과 ‘오늘 목표 교체’ 일반 설명을 날짜 갱신 안내로 대체한다. 전면 복귀와 저장 시 날짜를 재검사하되 적용일을 조용히 바꾸지 않는다.
- 적용일을 갱신하면 현재 목표·적용 시작일·현재 이력 표시·같은 날 교체 여부·동일값 저장 제한을 새 targetDay 기준으로 다시 계산한다. 사용자의 입력과 최초 dirty 비교 문자열은 덮어쓰지 않는다.
- 갱신 버튼을 누른 뒤 또 날짜가 바뀌면 동일 검사를 반복한다. 기기 시간대를 사용하는 기존 VM 계약을 유지한다.
- pending에서 재확인 성공하면 원래 날짜의 결과를 반영하고 닫는다. notApplied로 풀린 후 다시 저장할 때만 오늘 검사를 다시 한다.
- 저장 요청이 정상 접수된 뒤 처리 중 자정을 넘긴 경우에는 접수 시 검증된 날짜로 완료한다. 재확인 도중 날짜를 바꾸지 않는다.

## 저장·데이터 계약

기존 `GoalHistory`, `AppState.replaceGoal(on:with:)`, VM `perform`을 사용한다. schema와 저장소 구현을 바꾸지 않는다.

VM에 `setGoal(day:id:proteinText:completion:)`에 해당하는 진입점을 추가한다. pending/busy 검사 → 실제 오늘 검사 → 입력 파싱 → 기존 `perform` 호출 순서다. 필요하면 `.goalDateChanged` 같은 typed error를 추가하고 UI의 exhaustive switch를 모두 갱신한다.

VM에서도 파싱한 값이 대상 날짜의 현재 목표와 같고 `goalNeedsReview == false`이면 modify를 호출하지 않는 정상 no-op으로 처리한다. pending/busy·날짜·입력 검사는 먼저 수행한다. 검토 flag 정리가 필요하면 값이 같더라도 아래 원자적 저장을 수행한다.

하나의 modify에서 다음을 함께 수행한다.

1. 세션 목표 ID·표시 적용일·파싱한 양으로 만든 `ProteinGoal`을 `replaceGoal`로 저장.
2. `settings.goalNeedsReview = false`로 정리.
3. `legacyTargetRaw`, 이관 증거, 로그·합계·검색·즐겨찾기는 보존.

목표 ID는 편집 세션 중 유지한다. 다른 날짜의 기존 목표 ID를 재사용하지 않는다. operation ID는 기존대로 저장 시도마다 생성한다. 날짜를 명시적으로 갱신하는 경우에도 아직 커밋되지 않은 세션 목표 ID를 유지할 수 있다. 성공한 세션은 닫히므로 새 편집은 새 ID를 갖는다.

## 닫기와 저장 결과

Phase 1B의 `EditorDismissPolicy`, `SheetDismissAdapter`, 공통 확인/오류 표현을 재사용한다. 공유에 필요한 최소 UI만 internal 또는 공통 파일로 분리하고 기존 두 시트의 동작은 유지한다. 목표 화면에 삭제 동작은 추가하지 않는다.

| 상태 | 동작 |
| --- | --- |
| clean 취소/스와이프 | 쓰기 없이 닫기 |
| dirty 취소/스와이프 | 버리기 확인, 계속 입력은 값·날짜·ID 유지 |
| busy | 입력·저장·날짜 갱신·닫기 차단 |
| 저장 전 실패 | 입력과 기존 목표/flag 유지, 재시도 가능 |
| 미확정 | 입력·새 쓰기 잠금, 재확인과 미확정 닫기 제공 |
| 미확정 닫기 | 시트만 닫고 홈 배너·전역 쓰기 차단 유지, 초안 보존 약속 없음 |
| 재확인 반영 | 확인된 목표와 flag 적용 후 프로그램 닫기, 버리기 확인 없음 |
| 재확인 미반영 | 입력·ID 유지, 잠금 해제, 오늘 날짜 검사 후 다시 저장 가능 |
| 재확인 읽기 실패 | pending 유지, 실패 안내 후 다시 읽기 가능 |

확인창과 오류 alert는 중첩하지 않는다. 실제 확인 handler에서도 최신 busy/pending을 확인한다. 재확인은 읽기만 하며 자동 재저장하지 않는다. 앱 종료 후에는 디스크의 확인 가능한 상태가 기준이며 초안이나 메모리 pending의 복원을 새로 추가하지 않는다.

기존 저장 오류의 ‘기록이 바뀌지 않았다’는 문장을 재확인 읽기 실패에 그대로 사용하면 미확정을 확정 실패처럼 안내할 수 있다. 목표 시트에서는 중립적인 재확인 실패 문구를 사용하고 공통화 시 기존 기록 시트에도 의미가 맞는지 확인한다.

| VM/UI 테스트 | 목표 이력·원자성·자정·미확정·실제 닫기 경로 |
| `docs/evidence/<실행일>-goal-settings/` | 실행 명령·fixture·기기·기대/실제·캡처·미검증 |

Core의 기존 도메인 API를 읽고 재사용한다. UI 작업을 위해 `AppState`의 접근 수준을 느슨하게 하거나 별도 목표 저장 경로를 만들지 않는다.

## 구현 순서

1. 최신 main과 사용자 변경 확인. 계획의 오늘 전용 진입·자정 정책·범위 제외 사항을 읽고 합성 fixture 준비.
2. 목표 없음, 정상 이관 목표, 잘못된 raw, 이전 날짜 목표가 있는 VM 테스트부터 추가. 저장·review flag 원자성과 기존 데이터 보존을 고정.
3. VM 저장 진입과 날짜 검사를 구현. 기존 Core/Migration 계약을 유지.
4. 오늘 홈 진입과 목표 시트, 읽기 이력·한영 카피 구현. 필요한 공통 Phase 1B UI만 추출.
5. 목표 시트의 취소/스와이프/저장 실패/미확정/날짜 변경을 연결. 기존 기록·총량 시트 회귀 확인.
6. 독립 QA와 디자인·마케팅 검토. 실제 일반 iPhone 실행 증거와 한계를 기록.
7. 구현 결과에 맞게 docs/backlog 갱신하고 PR 작성·코드 리뷰. 머지와 출시 여부는 해당 시점 사용자 지시를 따른다.

## 검증 표

| 축 | 필수 확인 |
| --- | --- |
| 이력 | 최초 설정 이전 noHistory, 같은 날 재저장 1항목, 다음 날 변경 시 이전 목표 유지, 내림차순·현재 표시 |
| 입력 | 빈 값·문자·다른 구분자·소수 초과·0/음수·overflow, 소수점/쉼표 지역화, 동일값 저장 비활성 |
| 이관 값 | 정상 목표 prefill, invalid raw 원문/빈값/nil, 성공 때만 review false, raw와 이관 증거 보존 |
| 날짜 | 과거 홈에 편집 링크 없음, 저장일은 selectedDay와 독립, 자정 앞/뒤·날짜 되돌림, stale write0, 명시 갱신 후 재저장, 새 날짜에 기존 목표가 있을 때 표시·동일값 판정 재계산과 입력/snapshot 보존 |
| 실패 | 교체 전 실패는 파일·목표·flag 무변경, 입력 유지 |
| 미확정 | 실제 afterReplace와 대역 notApplied/readfail 구분, 시트/홈 재확인, pending 중 모든 쓰기 차단 |
| 날짜+pending | 전날 미확정의 applied는 전날 결과 확인; notApplied 후 재저장은 새 날짜 확인 필요 |
| 중복 | 빠른 저장 2회 modify 1회, 같은 세션 ID, 재확인은 load만, 동일 적용일 중복 없음 |
| 닫기 | clean/dirty/busy/pending × 취소/스와이프, 오류 확인창 경합, 성공 후 불필요한 버리기 확인 없음 |
| 재실행 | 확정 목표·flag 디스크 재로드, 초안 복원 없음, 중복 목표 없음 |
| 회귀 | 기록 추가/수정/삭제·총량·보정·날짜 탐색·원본 보존·Release 기본값 |

실제 파일 afterReplace 검증과 DEBUG/test adapter 검증을 혼동하지 않는다. 기존 `SaveOutcomeInjectingStore`를 재사용할 수 있으며 새 주입이 필요하면 Release에서 제외한다. 실제 사용자 파일 권한 변경이나 rollback으로 실패를 흉내 내지 않는다.

앱 Debug/Release 빌드, 관련 앱 테스트, Core/MigrationCore 회귀, `git diff --check`, 프로젝트와 strings 구문 검사를 수행한다. busy·자정은 clock/지연 대역으로 결정적으로 재현하고 단순히 저장이 빨라 못 봤다는 이유로 통과 처리하지 않는다.

SE 3세대와 일반 iPhone 17의 설치 가능한 런타임을 확인하고 한영·키보드·AX3에서 저장/닫기/이력 선택지를 실제 조작한다. VoiceOver 초점 복귀·발화는 실제 확인하거나 미검증으로 적는다. iOS 26.5 통과를 iOS 15 검증으로 표현하지 않는다. 건강 권장량을 계산하지 않으므로 의료 근거 조사나 계산기 로직은 이번 검증 범위에 없다.
