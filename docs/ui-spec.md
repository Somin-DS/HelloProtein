# UI 명세 초안: 화면 트리, 상태, 디자인 토큰

작성일: 2026-09-28. `docs/ui-direction-plan.md` C·D단계 산출물. **상태: 권장안 / 미확정.** 사용자 결정 전에는 제품 화면을 교체하지 않는다. 근거는 `docs/ui-audit.md`, 시안은 `docs/ui-preview/index.html`.

표기: **[기존]** 기존 앱에서 유지, **[Figma]** 디자이너 와이어프레임 의도(2026-09-23 검토 문서 기준), **[요구]** 사용자 요구, **[현재]** 현재 프로토타입에서 검증된 동작, **[새 제안]** 어떤 자료에도 없는 새 결정.

## 1. 권장 화면 트리

```text
시작 판정 (RenewalLaunchPolicy)                         [현재]
├─ 로딩 "데이터를 준비하는 중"
├─ 복구: 문제 종류 · 원본 보존 · (재시도)                [현재]
├─ 신규 사용자: 목표 설정 (직접 입력 + 계산기 시트)       [Figma][기존]
└─ 홈 = 선택 날짜의 기록 (기본: 오늘)                     [Figma][현재]
   ├─ 상단: 월 표시 · 오늘 복귀 · 달력 시트                 [현재]
   ├─ 날짜 띠 7일 (좌우 주 이동)                            [현재]
   ├─ 요약: 합계 · 목표 · 진행 막대 · 상태 문구             [Figma][현재]
   ├─ 이전 버전 합계 요약 → 상세 펼침 → 총량 편집 시트      [현재]
   ├─ 음식 목록 → 행 탭 → 편집 시트 (수정·삭제)             [현재]
   ├─ 하단 액션 바: [히스토리]  (＋ 추가)  [설정]           [Figma]
   │   ├─ 추가 시트: 직접 입력 | 검색 | 즐겨찾기 (탭)        [Figma]  *검색·즐겨찾기는 후속 구현*
   │   ├─ 히스토리: 캘린더 / 주간 그래프 → 날짜 탭 → 홈으로  [Figma][기존 통계]
   │   └─ 설정: 목표 · 검색 언어 · 문의 · 오픈소스 · 데이터  [기존]
   └─ 미확정 저장 배너 (홈 상단, 저장 결과 확인)            [현재]
```

### 1.1 구조 결정 (권장안 A)
- **홈 한 장 + 하단 액션 바.** 히스토리와 설정은 홈에서 push되는 화면이고, 탭이 아니다. 뒤로 가기는 항상 홈으로 온다. [Figma]의 "히스토리 / 중앙 추가 / 설정" 구성을 그대로 따르되, 탭 바처럼 보이지 않게 좌우 항목을 텍스트+아이콘 버튼으로, 중앙은 돌출된 원형 "＋"로 만든다.
- **추가는 동작이다.** 중앙 ＋ 는 화면 이동이 아니라 "선택 날짜에 기록 추가" 시트를 연다. 접근성 라벨은 "9월 23일에 단백질 추가"처럼 날짜를 포함한다. 탭 바 trait를 주지 않는다. [새 제안]
- **히스토리에서 날짜를 고르면 홈으로 돌아와 그 날짜를 선택한다.** 같은 기록 컴포넌트를 두 곳에 두지 않는다. 뒤로 가기로 히스토리에 다시 갈 필요가 없도록, 홈의 날짜 띠·달력이 이미 같은 이동을 제공한다. [새 제안]
- **선택 날짜는 앱 프로세스 안에서 유지한다.** 히스토리·설정에 갔다 와도 유지. 앱을 다시 열면 오늘. 자정이 지나면 `today`만 갱신하고 선택은 그대로(현재 구현). [현재]
- **목표 편집 진입점**: 주 진입은 설정 > 목표. 보조 진입은 홈 요약의 "목표 없음 → 목표 설정" 링크(목표가 없을 때만). 과거 날짜에서는 목표 편집 링크를 두지 않는다(소급 금지). [새 제안][계약]
- **저장하지 않은 입력이 있을 때**: 시트를 닫으려 하면(취소·스와이프) "입력을 버릴까요?" 확인. 날짜 변경·뒤로 가기는 시트가 열려 있는 동안 불가(시트가 모달). 저장 중에는 닫기 자체가 비활성. 미확정 중에는 닫기를 허용하되(홈 배너가 이어받음) 확인 대화상자로 "입력한 내용은 남지 않는다"를 알린다. 정책 세부는 §3.3. [현재][새 제안(확인 대화상자)]

### 1.2 대안 B (구조적 대안, 같은 조건으로 비교)
- 3탭(기록 / 히스토리 / 설정) + 기록 탭 안의 FAB. 장점: iOS 관례, 각 탭 상태 독립. 단점: 히스토리에서 고른 날짜와 기록 탭의 선택 날짜가 둘이 되어 "어느 날짜에 추가되는가"가 모호해진다. 하단 세 자리 중 하나가 "설정"이라는 저빈도 화면에 고정된다. 시안에서 토글로 비교할 수 있다.
- 권장: A. 이유는 사용자 요구가 "과거 조회·편집"이며, 그 흐름은 날짜 하나를 가진 홈 한 장이 가장 짧다.

## 2. 핵심 흐름 (시안에서 따라갈 수 있어야 함)

| # | 흐름 | 화면 순서 | 계약 |
| --- | --- | --- | --- |
| 1 | 기존 사용자 오늘 기록 | 홈(오늘) → ＋ → 직접 입력 → 저장 → 홈 갱신 | 저장 성공 후에만 목록·합계 반영 |
| 2 | 과거 누락 보완 | 날짜 띠 또는 달력 → 과거 날짜 → ＋ → 저장 → 같은 날짜 유지 | 편집 대상 날짜는 시트 열 때 고정 |
| 3 | 과거 수정 | 행 탭 → 편집 시트 → 수정/삭제 → 합계 갱신 | ID·날짜·source 유지 |
| 4 | 합계 전용 | 과거 날짜 → "이전 버전 합계 70g" 요약 → 펼침 → 총량 수정 또는 ＋ | 가짜 음식 상세 생성 금지, 보정값 = 총량 − 상세 합 |
| 5 | 신규 사용자 | 목표 입력(계산기는 보조 시트) → 시작 → 홈 | 기존 사용자에게 재노출 없음 |
| 6 | 목표 변경 | 설정 > 목표 → 값·적용일(오늘부터) 확인 → 저장 → 오늘부터 반영 | 과거 목표 추정 금지 |
| 7 | 저장 실패 | 저장 → 실패 알림 → 시트·입력 유지 → 재시도 | 입력 보존 |
| 8 | 결과 미확정 | 저장 → 미확정 알림 → 입력 잠금 + "저장 결과 확인" → 확정(닫힘) 또는 미반영(입력 재개) | 자동 재저장 금지 |

## 3. 화면별 상태와 인터랙션

### 3.1 홈
| 상태 | 표시 |
| --- | --- |
| 오늘 빈 상태 | 합계 `0 g`, 목표 막대 0%, 목록 자리에 "첫 기록을 추가해보세요" + 화살표 없이 ＋ 를 가리키는 문장 |
| 기록 있음 | 합계 큰 숫자, 막대, "목표 120g · 65g 남음" |
| 목표 없음 | 막대 없음, "목표를 아직 설정하지 않았어요 · 목표 설정" 링크 |
| 목표 초과 | 막대 100% 채움 + 초과분을 막대 밖 숫자로 "목표 +12g", 달성 체크 아이콘. 막대가 100%를 넘지 않음 |
| 이력 없는 과거 날짜 | 막대 없음, "이 날짜의 목표 이력이 없어요"(달성/미달 추정 금지) |
| 미확정 저장 | 상단 경고 밴드 + "저장 결과 확인". ＋·행·총량 편집 비활성 |

- 날짜 띠: 요일 약자(위) + 일(아래). 선택 = 잉크색 채움 + 크림 글자. 오늘 = 아래 작은 점(선택 여부와 무관). 기록이 있는 날은 일 숫자 아래 얇은 녹색 밑줄(있음/없음만, 달성 아님). [새 제안]
- 진행 막대: 높이 8, 트랙 `line`, 채움 `brand.green`, 손잡이 없음, `accessibilityValue` "목표의 46%". 애니메이션은 0.3초 이하, `reduceMotion`이면 없음.
- 이전 버전 합계: 기본은 한 줄 "이전 버전 합계 70g ⓘ". 펼치면 "가져온 원본 70g / 지금 총량 80g (음식 10g + 이전 합계 70g) / 총량 수정" 표시. 보정값이 음수면 "이전 합계 −5g"로 부호를 그대로 보인다.

### 3.2 추가/편집 시트
- 필드: 음식 이름(선택), 단백질(g, 소수 2자리, 숫자 키패드), 날짜(읽기 전용, 시트 제목 아래).
- 상태: 직접 입력 / 검증 오류(필드 아래 인라인 문구 + 저장 시 알림) / 키보드 표시(저장 버튼이 키보드 위 액세서리에도 있음) / 저장 중(스피너, 취소·저장·필드 비활성) / 저장 실패(알림, 시트·입력 유지).
- 편집 시 삭제는 시트 하단 빨간 텍스트 버튼 + 확인 대화상자.
- 탭(직접 입력 | 검색 | 즐겨찾기)은 시안에만 있고, 구현 전까지는 직접 입력만 노출한다. 아직 없는 기능을 제품 화면에 넣지 않는다.

### 3.3 미확정 저장
| 상태 | 표시 |
| --- | --- |
| 필드 잠금 | 필드 회색, 시트 안 경고 카드 "저장 결과를 확인하지 못했어요 · 저장 결과 확인" |
| 재확인 가능 | 버튼 활성. 취소는 저장 중이 아니면 활성 |
| 미확정 중 닫기 | 취소·스와이프 시 확인 "저장 결과를 아직 확인하지 못했어요 · 닫아도 홈에서 확인할 수 있어요. 입력한 내용은 남지 않아요" → 닫기/계속 쓰기. 닫으면 홈 배너와 "저장 결과 확인"이 이어받는다. **입력 초안은 보존하지 않는다**: 미반영으로 판명되면 다시 입력한다. 미확정 상태 자체(`pendingSave`)는 시트와 무관하게 유지된다. [현재(닫기 허용)][새 제안(확인 대화상자)] |
| 재확인 실패 | 알림 "아직 파일을 읽을 수 없어요", 잠금 유지 |
| 재확인 실패 후 | 잠금·취소 정책은 최초 미확정과 같다(닫기 허용 + 확인) |
| 미반영 후 입력 재개 | 알림 "저장되지 않았어요 · 입력이 남아 있어요", 필드 잠금 해제, 저장 버튼 활성 |

### 3.4 목표
| 상태 | 표시 |
| --- | --- |
| 기존 목표 | 현재 목표 120g, 적용일 "2026-09-28부터", 새 값 입력 |
| 신규 입력 | 빈 필드 + "계산기로 정하기" 링크(시트) |
| 잘못된 기존 값 | "이전 버전의 목표 'abc'를 사용할 수 없어요" + 원문 유지, 새 값 입력 유도 |
| 과거 이력 없음 | 목표 화면이 아니라 홈 요약에서만 표시 |
- 계산기: 몸무게(kg/lb) + 활동량 3단계 → 결과를 목표 필드에 채움. 임신·수유·고령 옵션은 근거 확인 전 넣지 않는다. [기존 계산식 유지][Figma 옵션 보류]

### 3.5 검색/즐겨찾기 (설계만, 후속 구현)
- 추가 시트의 탭. 검색창·탭 고정, 목록만 스크롤. 결과 행: 이름(2줄까지), 단백질 g/100g, 체크. 하단 고정 "3개 · 42g 추가" 버튼. 즐겨찾기 빈 상태 "저장한 음식이 없어요 · 직접 입력 후 별을 눌러 저장". 긴 영어 이름은 2줄 후 말줄임.

### 3.6 히스토리
- 상단 세그먼트 캘린더 | 그래프. 캘린더: 월 이동, 기록 있는 날 점, 합계만 있는 날 빈 점(테두리만) [새 제안]. 그래프: 주간 막대 7개 + 목표 가로선, 명시적 주 이동 화살표(확대 제스처만으로 이동하지 않음). 날짜 탭 → 홈으로 이동해 선택.
- 평균은 "기록이 있는 날 평균"으로 라벨을 붙인다. [기존 계산 방식 유지]
- 그래프의 목표선은 홈과 같은 날짜별 목표 이력(`goal(on:)`)을 쓴다. 그 주 7일 모두 이력이 없으면 목표선을 그리지 않고 "이 주에는 목표 이력이 없어요"를 표시한다. 주 중간에 목표가 바뀌면 날짜별 눈금으로 표시한다. 과거 주에 현재 목표를 소급 적용하지 않는다. [계약]

### 3.7 복구
- 제목 "데이터를 옮기지 못했어요", 문제 문장, "원본은 그대로 있어요" 문장(항상), 백업 문장(있을 때), 재시도 가능하면 채움 버튼 "다시 시도", 불가하면 버튼 없이 "이 상태는 자동으로 해결되지 않아요. 문의하기" 링크. 상세 코드는 footnote. 초기화·삭제 버튼 없음. [현재][새 제안(문의 링크)]

### 3.8 온보딩 (신규 사용자만)
- 워드마크(기존 이미지) + "하루 목표를 정해주세요" + 목표 입력 + "계산기로 정하기" + "시작". 뒤로 가기 없음. 기존 사용자·이관 사용자에게는 표시하지 않는다. [기존][Figma]

### 4.4 간격·형태
- 화면 여백 20. 목록 행 높이 ≥ 56, 행 안 좌우 20. 카드 안 여백 16. 섹션 간격 24.
- 모서리: 카드·시트 16, 버튼 12, 칩 8, 원형 ＋ 28(지름 56). 기존의 5·10·15·20·25 혼용을 셋으로 줄인다. [새 제안]
- 테두리: 카드는 `line` 1pt, 그림자 없음(기존 앱과 동일).
- 터치 목표 최소 44×44. 하단 액션 바 높이 64 + 안전 영역.
