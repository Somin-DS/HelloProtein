## 근거

`AppState.swift`, `RecordDomain.swift`, 이관 mapper/builder, 기존 `AddViewController`·`SearchViewController`·검색 DTO·영문 JSON, Phase 1B와 목표 구현, ui-spec와 backlog를 읽었다. 영문 JSON에는 2,332행의 Food/Protein만 있으며 기준량·출처·공급자 ID가 없다. 개발 검토에서 0g 항목 144개도 확인했다. 이 집계는 영양값의 정확성이나 외부 API의 현재 계약 검증이 아니다.

## 의견 조정

1. **탭 초안:** 초기 기획은 탭별 보존, 초기 디자인은 공유 선택 또는 확인 전환을 제안했다. 숨은 초안이 다른 탭 저장 후 사라지는 문제를 피하고 범위를 줄이기 위해 최종안은 dirty 확인 후 ‘버리고 이동’이다. 현재 탭 하나만 저장 대상으로 삼는다.
2. **최근 검색:** 개발은 기록 추가와 검색어를 원자적으로 저장하고 ‘최근 사용 검색어’로 의미를 바꾸는 안을 권했다. 기획은 기존 명시 검색 실행 이력을 보존해야 한다고 판단했다. 최종안은 B에서 명시 검색 실행마다 별도 저장 작업을 두되, pending 소유권과 성공 후처리를 기록 추가와 분리한다. 이력 재확인 성공이 음식 추가 완료나 시트 닫기로 이어지지 않도록 했다.
3. **position:** 개발은 관리마다 연속 재번호를 제안했다. 최종안은 favorite 추가는 checked max+1, overflow일 때만 원래 순서 유지 재번호로 좁혔다. 검색 이력은 재검색 시 맨 앞으로 이동하므로 그 transaction에서 연속 position을 재구성한다. ID·원문·legacySourceID는 유지한다.
4. **기존 invalid favorite:** 자동 삭제/보정 대신 원문 표시·선택 차단·실제 편집 경로를 A에 포함한다. 새로운 무료 개수 제한은 없다.
5. **검색 기준량:** 기존 문구의 100g을 사실 근거로 쓰지 않는다. B에서 공식 문서·응답·영문 파일 근거를 확인한 뒤 자동 추가를 허용한다. 미확인 상태의 이름 복사 fallback을 검색 복원 완료로 표시하지 않는다.

## 실행 범위

이번 작업은 문서 작성뿐이다. 제품·테스트 코드 수정, 빌드·시뮬레이터 실행, 외부 메시지, 커밋·PR·머지를 하지 않았다. Figma 원본과 외부 공급자 문서·현재 동작은 이번에 확인하지 않았다. 계획 검토 동의는 구현 QA 통과나 출시 승인이 아니다.
