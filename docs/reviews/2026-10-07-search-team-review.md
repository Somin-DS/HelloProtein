## 확인한 근거

현재 `AddSheet`, `AddSheetPolicy`, `RecordHomeViewModel`, `FoodRow`, Core의 `SearchTerm`·`SearchLanguageSetting`·`FoodQuantity`·`FoodRecord`, 기존 `SearchViewController`와 `ProteinModel`, 영문 JSON, 기존 A/B 계획과 PR #8 검증 기록을 근거로 했다. 영문 파일 2,332행, Food/Protein 두 필드, 0g 144행은 로컬 집계로 확인했다. 이 집계는 영양 정확성·출처·이용 조건을 증명하지 않는다.

외부 공급자의 공식 계약·현재 응답과 Figma 원본은 이번 검토에서 확인하지 않았다. 공급자 사실 확인은 계획의 첫 실행 단계 B0이며, Figma 새 화면 승인이나 현재 API 사용 가능 판정을 대신하지 않는다.

## 의견 조정과 최종 결정

1. **공급자 근거와 완료 판정:** 기존 파일을 바로 연결하는 안은 기준량·출처가 없어 채택하지 않았다. 기존 무료 기능 복원이 목표지만 데이터 사용 조건과 분모가 확인돼야 자동 기록이 가능하다. 일부 공급자 또는 fallback만 구현하면 부분 완료로 보고한다. 새 공급자·유료 계약·백엔드가 필요하면 별도 범위 결정으로 분리한다.
2. **검색과 이력 저장:** 최근 검색은 명시적 검색 실행 이력을 유지한다. 이력 저장 실패와 검색 실패는 별도다. 최초 callback에서 유효 요청을 한 번 시작할 수 있으나 재확인에서 재검색·이력 재쓰기를 자동 실행하지 않는다. 더 보기와 요청 재시도는 이력을 새로 저장하지 않는다.
3. **언어 변경 실패:** 버리기 확인을 눌렀다고 즉시 선택을 삭제하지 않는다. 저장 반영 확인 전까지 결과·선택·record ID·queryDraft를 유지하고, 반영 확인 후 결과·선택을 비운다. 요청 취소는 스냅샷 삭제와 구별한다. 확정 실패·미반영은 이전 확인 언어와 선택을 유지한다.
4. **이름 복사 전환:** 기준량 불명 행은 이름만 직접 입력으로 전달할 수 있다. 선택 버림 확인, 취소 시 원상태, 단백질 공란·즐겨찾기 OFF·고정 날짜 보존을 하나의 전환으로 정의한다. 일반 탭 이동이 복사 초안을 다시 지우지 않도록 한다.
5. **기준량의 수명:** 검색 결과의 검증된 quantity를 기록과 함께 저장하고 홈·편집 화면 및 VoiceOver에서 읽을 수 있게 한다. 사용자가 기록 단백질을 편집해도 수량은 보존하되 공급자 인증값이라고 표시하지 않는다. 공급자 정보를 레거시 ID 필드에 넣지 않는다.
6. **수익화와 평가:** 이번에는 무료 핵심 검색을 복원한다. 새 구독·광고·AI·분석 SDK는 제외한다. 대표 검색에서 기준량을 확인하고 원하는 날짜에 기록되는지, 수동 우회가 필요했는지를 실행 증거로 남긴다. 다운로드 수를 현재 활성 사용자나 수익 잠재력으로 환산하지 않는다.

## 최종 문서 재검토

3개 에이전트가 실제 `docs/search-implementation-plan.md` 초안을 다시 읽고 7개 직무 관점으로 대조했다. 기획·그로스는 문서 합의했고, 디자인·마케팅은 필수 충돌 없이 합의하며 4개 상태 문구를 보완하도록 권고했다. 개발·QA·프롬프트는 전반 계약에 합의하며 언어 저장의 선택 보존 시점을 더 명확히 하도록 지적했다.

최종본에 언어 저장 반영 전 결과·선택·record ID·queryDraft 보존, 해당 실패 회귀 검증, FoodRow의 VoiceOver 기준량 표시, 상태별 한영 문구 4개, 대표 사용자 흐름 성공·우회 이유 기록을 반영했다. 문서 합의는 구현 QA 통과나 출시 승인을 의미하지 않는다.

이번 산출은 계획과 이 검토 기록, 기존 계획·로드맵의 연결 문서 수정뿐이다. 제품·테스트 코드 변경, 새 빌드·시뮬레이터 실행, 외부 메시지, 커밋·PR 생성·머지는 하지 않았다.
